# BASIC in portable C89

A C89 version of the BASIC interpreter, written to run later on VM/370 (CMS).
It reads the same programs and passes the same regression tests
(`../tests/*.bas`) as the CREXX version `../basic.crexx`, with identical output.
Layout, rules and checks follow `mikebeer/apl` and the Smalltalk port.

    make                  # builds ./basic from the single file basic_all.c
    make test             # runs ../tests against ./basic
    make strict           # gcc + clang -std=c89 -pedantic-errors, sanitizers (tools/strict.sh)
    make deck             # deck/basic_deck.c: every line at most 71 columns
    make check            # tools/vm370_check.py on basic_all.c and the deck
    make bench            # runs ../bench/*.bas (prints milliseconds)
    ./basic [-fb|-ms] [-ansi] [-dump] prog.bas [args]
    ./basic               # interactive prompt (RUN, LIST, NEW, LOAD "f", SYSTEM)

## Layout

    src/b0_base.c    includes, types, global state
    src/b_proto.h    prototypes of all functions (generated by tools/protos.sh)
    src/b1_util.c    memory, strings, hash maps, number formatting, 64-bit helpers
    src/b2_lex.c     program loading, variable slots, tokenizer, DATA
    src/b3_link.c    link pass: blocks, procedures, DEF FN, parameters
    src/b4_expr.c    errors, arrays, expressions, calls, builtin functions
    src/b5_stmt.c    PRINT [USING], INPUT, files, the statement executor
    src/b6_main.c    run_program, token dump, interactive mode, main
    src/basic.c      includes the parts; tools/amalg.sh inlines them into
    basic_all.c      ONE self-contained source file (generated; checked in)
    deck/basic_deck.c  the same, re-wrapped to 71 columns (tools/deck.py; generated)
    tools/           amalg.sh, protos.sh, strict.sh, deck.py, vm370_check.py
    tests/           run_tests.sh [interpreter], skip.txt (tests not run, none at present)

The interpreter is a straight port of `basic.crexx`: the same token array,
link pass and executor, with the same numeric codes for keywords, so the
`-dump` output of the two versions is identical.  After changing `src/`
run `make` (it regenerates `src/b_proto.h` and `basic_all.c`) and commit
the generated files.

## Portability rules

* Strict C89: no `//`, no declarations after statements, no `long long`, no
  `stdint.h`, no C99 library functions (`snprintf`, `trunc`, `log2`, `isnan`...).
  `gcc/clang -std=c89 -pedantic -Wall -Wextra` is clean (`make strict` also
  uses `-Wconversion -Wshadow` and checks the object for C99 symbols).
* All functions are `static`; the only external symbol is `main`.
* Character classes use literal sets (`"ABC...Z"`), never code point ranges or
  arithmetic; no `??` sequences (trigraphs) and no source line over 71 columns
  in the deck.
* POSIX is only used with `-DBASIC_POSIX` (`gettimeofday` for fractional
  `TIMER`).  The `make` target defines it; without it the program is plain C89.
* `long` may be 32 bits (VM/370).  Counts and subscripts are limited to
  +-1e9.  The bit operators, `HEX$`, `OCT$` and `BIN$` use a 64-bit two's
  complement value held in two 32-bit halves, so they give the CREXX results
  on any host.  Checked with `gcc -m32`.
* Arrays, tokens, variables and stacks are plain arrays grown with `realloc`;
  never keep a pointer into them across a call that can evaluate BASIC code.

## Number formatting

CREXX prints a float through its decimal converter.  The C code reproduces that
algorithm (`fmt_float` in `b1_util.c`): the value is normalised with
`floor(log10(x))` and `pow(10, e)`, written with `%.14f` (15 significant digits),
trailing zeros are removed, and the exponent form is used only when the exponent
is below -6 or above 17.  Whole numbers below 1e15 are printed from their exact
integer digits.  RND uses the same Park-Miller generator with exact double
arithmetic, so a seeded sequence is the same in both versions.

## Differences from the CREXX version

* Strings are byte strings.  CREXX counts UTF-8 characters (`LEN("é")` is 1,
  `CHR$(200)` is U+00C8, `UCASE$` maps non-ASCII letters); the C version works
  on bytes and `CHR$(n)` gives the low byte of `n`.  Programs and tests that
  stay inside 7-bit text behave identically.
* `&HFFFFFFFFFFFFFFFF` (16 hex digits with the top bit set) gives 1.8E+19; the
  CREXX conversion returns 16 for it.  A literal such as `5E-324`, which makes
  the CREXX interpreter stop with a conversion error, is read normally.
* Integer division and `MOD` of values beyond 2^53 use doubles.

## Checked

gcc and clang with `-std=c89 -pedantic-errors`; AddressSanitizer and UBSan clean
on all tests; `gcc -m32` gives the same results; the 71-column deck builds,
passes `tools/vm370_check.py` (no errors) and the tests.  The 115 expression
probes and the extra control-flow programs used while porting print the same
as the CREXX version.

## Speed

`../bench/run_bench.sh` runs five programs (loops, nested loops, string
building, insertion sort, prime sieve) with deterministic output; pass `./basic`
(from the repository root) to time the CREXX version instead.  The C version is
roughly 30 to 100 times faster.
